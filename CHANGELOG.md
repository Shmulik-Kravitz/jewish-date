# Changelog

## 2.0.29

- chore: Removed the last runtime dependency. The `gematriya` package (and its `@types/gematriya` types) has been replaced by an internal Gematria implementation in `src/utils/gematriaUtils`, so `jewish-date` now installs with zero runtime dependencies. The public API is unchanged and the Hebrew output is identical: `convertNumberToHebrew`, `convertYearToShortHebrew`, `toHebrewJewishDate` and `formatJewishDateInHebrew` all return exactly what they did before. The new implementation was diffed against the previous library over 126,041 cases — every number from 0 to 30,000 across all four `geresh`/`punctuate` combinations, plus the default options and edge inputs — with no differences. The existing behaviour is preserved deliberately, including the letter substitutions that avoid spelling a name of God (15 as `טו`, 16 as `טז`) and the restart of the letter cycle above a thousand.
- chore: Fixed two problems in the release workflow. The changelog section for a release is now written as `## Unreleased` and stamped with the real version number by CI once `yarn inc-version` has run, so the `Create GitHub Release` step finds the notes it has always looked for instead of silently falling back to auto-generated ones. The release tag is also created after the release commit rather than before it, so a tag no longer points one commit behind and names a tree whose `package.json` still holds the previous version. Every existing tag from `v1.0.1` to `v2.0.28` carried that off-by-one and has been moved onto its version bump commit, so checking out any release tag now gives the tree that was actually published under that version.

## 2.0.28

Nothing in this release changes what the package does. The API, the conversion
results and the formatted output are all identical to 2.0.27, so upgrading needs
no code changes.

The work was internal: build, test and CI tooling. The one difference inside the
published files is that the bundled type declarations are now generated by
TypeScript 7, which prints one internal helper type's key union in a different
order. That type is not reachable from the package entry point, so nothing you
can import has changed.

## 2.0.23

- feat: `formatJewishDate` and `formatJewishDateInHebrew` now accept an optional format pattern as a second argument, using tokens similar to [date-fns](https://date-fns.org/docs/format). Lowercase tokens (`d`, `dd`, `M`, `MM`, `yy`, `yyyy`) output numeric values, uppercase tokens (`D`, `YY`, `YYYY`) output gematria in `formatJewishDateInHebrew`, and `MMMM` outputs the month name. Defaults are `"d MMMM yyyy"` for `formatJewishDate` and `"D MMMM YYYY"` for `formatJewishDateInHebrew`, so existing output is unchanged.
- chore: Reworked the GitHub Actions workflow to build, test and publish to npm automatically, and upgraded CI to Node.js 24.
